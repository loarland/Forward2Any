服务

改端口会在本进程内立即重新绑定监听，不用重启。 但如果跑在 Docker 里，还得同步改 docker-compose.yml 的端口映射，否则容器外访问不到； 这时候建议把「回调基址」也一并改成外部实际访问的地址。

跨站请求校验

{{/* 复选框后面跟一个同名 hidden：没勾时也能读到明确的 "0"（同名取第一个值） */}}
后台的写操作（登录、保存设置等）会核对请求的 Origin（没有就看 Referer），不一致就返回 403，防的是别的站点伪造请求。
用 IP:端口 直接访问时两边天然一致，不用配任何东西； 套了反向代理、而代理改写了 Host（nginx 没写 proxy_set_header Host 就会）时， 把浏览器里访问用的地址填到上面，例如 https://hooks.example.com。
只写主机名（hooks.example.com）表示协议不限，写全 https:// 开头的就只认那个协议；「回调基址」里的主机名默认就认，不用重复填。
关掉开关就不校验来源，只剩会话 cookie 的 SameSite 兜着，一般不需要关。

反向代理

只有当请求的直连地址落在这个列表里时，才采纳 X-Forwarded-For 里的客户端地址作为真实来源；其它情况一律按直连对端地址算 —— 这个头谁都能伪造。
它决定三处看到的是谁：登录失败限流的计数键、源的「来源 IP 白名单」、日志里的来源 IP。
服务直接暴露（前面没有代理）时留空；套了 nginx 就在上面填代理自己的地址， 并让代理转交客户端地址：proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;。

网络代理

这里配好的代理不会自动生效：还要到「源」里勾上通过代理发送， 那个源的 Webhook 投递才会走它。没勾的源、以及邮件发送（SMTP），一律直连。
需要认证就把账号密码写进地址：用户名:密码@127.0.0.1:7890， HTTP / HTTPS / SOCKS5 三种都支持。
HTTPS 指的是到代理这一段用 TLS 连接，不是「用它访问 https 站点」—— 三种类型都能访问 https 目标。
代理连不上时投递会直接失败并记进日志，不会偷偷改回直连。

安全设置

默认关闭：关着的时候登录页不加载任何外部脚本。开启后，登录必须先通过 Cloudflare Turnstile 的人机校验，服务端拿到 token 会再去 Cloudflare 校验一次（只靠前端控件可以被绕过）。
密钥在 Cloudflare 控制台 → Turnstile → 添加站点里拿；域名填你访问后台用的那个。
被盾挡在门外怎么办：用 F2A_TURNSTILE=off 重启进程 （或先删掉数据库里 turnstile_enabled 这个键），登录就不再要求校验。
校验请求由服务器发往 challenges.cloudflare.com；要经由自己的中转， 用 F2A_TURNSTILE_ENDPOINT 指定地址。

投递与日志

重试间隔按「基数 × 2次数-1」往上翻，最长不超过 1 小时。 次数用尽后状态变成「已放弃」，不会自动再试，但可以在投递详情页手动重新投递。
「报文保存上限」指的是每条投递记录最多存多少字节的报文，超出的部分会被截断后入库。

导入
导出把一个 JSON 文件写到本地，用来备份或换台机器部署。文件里有两部分：
· 全部源与规则（规则按文件内部的源下标引用源，不含数据库主键）；
· 设置里的回调基址，以及「投递与日志」的四项参数（重试次数、退避基数、报文上限、日志保留天数）。
文件里不含管理员账号与密码、监听端口、代理、时区、外观、Turnstile 密钥 —— 这些是本机自己的事，换机器后重新设一遍。
导入是整体替换：文件里没有的源与规则会被删掉，文件里带着的设置项覆盖本机同名项， 文件里没带的设置项保持原样。整份文件先校验后落库，任何一处不合法都当作没导入过。
源里的密钥（Webhook 密钥、SMTP / IMAP 密码、Telegram Bot Token、渠道加签密钥）原样导出， 这个文件是敏感文件：不要提交到 Git，也不要通过聊天工具或邮件外发。
