全部条件都满足才转发；不添加条件时所有消息都会被转发
还没有条件
一行一条，格式是 路径 操作符 值。 以 # 开头的行是注释（注释只在文本模式下保留，切回可视化会丢）。
「路径」照着入站报文的 JSON 写，用点号一层层往下。 报文是 {"repository":{"private":false}}，路径就写 repository.private；数组用下标，commits.0.id 是第 1 个提交的 id。
「值」按 JSON 解析：true 是布尔、123 是数字、 [1,2] 是数组；不加引号的裸词（比如 push）当字符串。 要精确匹配带空格的值就加引号："带 空格"。
几条条件是「全部满足」才转发，所以「带 [skip] 的不转发」要写成不包含。 只想转发非私有仓库的 push，就是这样三条：
action等于push
repository.private等于false
commits.0.message不包含[skip]
想反过来（命中任意一条就转发）现在不支持，得拆成多条规则。

模板转换

这三格留空就原样转发，不需要模板也能用。 填了就是用 Go template 把入站报文重新拼一遍：{{ }} 里写变量或函数，外面的字原样保留。
.Payload 入站报文解析出来的 JSON，用点号一层层往下取。报文不是 JSON 时，它是 {"raw": "原始报文"}。
.Raw 原始报文字符串，一个字都没动过的。
.Source 接收源的信息：.name、.slug、.kind、.id。
.Headers 入站请求头。邮件源里放的是 Message-Id、Subject、From 这些。
.TraceID 这次入站请求的追踪号，和投递日志详情页上显示的那个是同一个，排查时靠它串起来。
.Now 当前时间。{{.Now.Format "2006-01-02 15:04"}} 就能格式化成 2026-09-20 18:30。
长度、格式化这类用内置函数，比如 {{len .Payload.commits}}。
完整例子：GitHub 推过来的是 {"repository":{"full_name":"a/b"},"commits":[1,2,3]}。 在「报文体模板」里写 {{.Payload.repository.full_name}} 收到 {{len .Payload.commits}} 个提交， 实际发出去的就是 a/b 收到 3 个提交。
两个坑： 一是取数组元素必须写 {{index .Payload.commits 0}}， 不能像上面「过滤条件」那样写 .commits.0（那是过滤器的语法，模板里会直接报语法错，保存时就挡下来）。 二是「请求头模板」不是文本模板而是 JSON 对象，值里才能嵌模板， 比如 {"X-Source": "{{.Source.slug}}"}，填错 JSON 保存时也会报错。
