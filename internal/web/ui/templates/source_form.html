Webhook 接收

{{/* 四种鉴权方式要填的东西差别很大，所以按选择切换说明。 四段都渲染出来、只有当前那段不带 hidden —— 这样没有 JS 时也能看到对的说明， app.js 只负责在选择变化时换个显示。 */}}
不校验：任何知道这个回调地址的人都能往里面发消息。 只适合内网、或者上游确实没法带密钥的情况。如果只能用这个，建议在上面配一条 IP 白名单，至少限制一下来源。
固定密钥：上游在请求头里带上一串约定的字符就行，最好接、也最常用。
请求头名密钥放在哪个头里，默认 X-F2A-Token，改成别的名字也行。
密钥两边约定好的那串字符。上游发的值必须和它完全一致。
上游要发的是：X-F2A-Token: 你的密钥
HMAC-SHA256 签名：拿密钥对原始报文算一次 HMAC-SHA256， 把十六进制结果放进请求头。报文只要被动过一个字节签名就对不上，所以比固定密钥安全。 GitHub、Gitea 的 Webhook 默认就是这个方式。
请求头名签名放哪个头，默认 X-Hub-Signature-256（跟 GitHub 一致）。
密钥你在上游填的那个 Webhook Secret，两边必须一样。
上游要发的是：X-Hub-Signature-256: sha256=<十六进制摘要>
HTTP Basic：标准的 Authorization: Basic base64(用户名:密码)，浏览器和 curl 都原生支持。
请求头名这里当用户名填。
密钥这里当密码填。
用 curl 测试就是：curl -u '用户名:密码' <回调地址>
保存后会得到一个回调地址 /hook/<路径标识>，把它填到发送方即可。 如果后台挂在了 Nginx 之类的反代后面，IP 白名单里要填反代的地址， 因为程序看到的是直接连上来的那个 IP。

接收默认模板

这个源收到消息时，先按这两份模板把报文渲染一遍，再交给规则；规则里自己填了模板就以规则为准。
变量和规则里的模板完全一样：{{.Payload.字段}}（解析后的 JSON）、 {{.Raw}}、{{.Headers}}、 {{.Source.name}}。
典型用法：上游推过来的是 {"title":"…","content":"…"}， 这里写 {{.Payload.title}} / {{.Payload.content}}， 之后每条规则、每个目标（邮件、钉钉、飞书…）拿到的就都是干净的标题和正文。
投递日志里的「原始报文（入站）」仍然记录入站原文，方便对照。
{{/* 地址只有一格，不给每个渠道各放一个同名的输入框：隐藏起来的面板照样会把值提交上来， 同一个 name 出现两次时服务端只会读第一个，等于把用户填的地址丢了。 */}}

推送地址

自定义 Webhook：目标地址原样收下报文。请求方法、固定请求头见下面一块； 报文内容由规则的「报文体模板」决定，模板留空就是原样透传入站报文。 想让别的服务认得出这条消息，就按它的文档在规则里写模板。
钉钉群机器人：群设置 → 智能群助手 → 添加机器人 → 自定义 → 复制 Webhook， 形如 https://oapi.dingtalk.com/robot/send?access_token=…。
安全设置选「自定义关键词」时，消息里必须带上那个关键词；选「加签」时把密钥填到下面的加签密钥里。 机器人限速 20 条/分钟，超了会被临时限流。
企业微信群机器人：群设置 → 群机器人 → 添加 → 复制 Webhook， 形如 https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…。
正文按 markdown 发出（企业微信只支持它的一个子集），单条上限 4096 字节。
飞书群机器人：群设置 → 群机器人 → 添加 → 自定义机器人 → 复制 Webhook， 形如 https://open.feishu.cn/open-apis/bot/v2/hook/…。
正文发的是互动卡片（标题 + markdown 正文）。如果安全设置开了「签名校验」， 把签名密钥填到下面的加签密钥里，不然会被拒。
Bark：填 Bark App 里那条推送地址， 形如 https://api.day.app/<你的 key>（自建的换成自己的域名）。
正文按 markdown 发出；想给它归个组就在下面填分组名，不填就不分组。
Server酱：在 sct.ftqq.com 拿到 SendKey 后， 地址形如 https://sctapi.ftqq.com/<SendKey>.send。
标题来自规则的「邮件主题模板」（留空会用默认标题），正文是渲染后的报文。
WxPusher：用它的「极简推送」——扫码后复制那条带 SPT_ 的地址，形如 https://wxpusher.zjiecode.com/api/send/message/SPT_xxxxxx。
程序会把 SPT 抽出来打到 simple-push 接口上，正文按 markdown 发送。
Gotify：在 Gotify 里建一个应用，地址形如 https://gotify.example.com/message?token=<应用令牌>（末尾的 /message 别丢）。
标题来自「邮件主题模板」，正文按 markdown 发送，优先级固定 5。
OneBot（QQ 等）：填实现（go-cqhttp / NapCat / Lagrange 之类）的 HTTP 接口地址， 私聊用 /send_private_msg、群聊用 /send_group_msg，必要时把 ?access_token=… 一起带上。
目标 ID 填在下面的「目标 ID」里（私聊写 QQ 号，群聊写群号；写成 user:123 / group:123 更明确）。
消息按纯文本发出，标题 + 换行 + 正文。

渠道参数

内置渠道的报文格式由程序按类型拼（钉钉 / 企业微信 / 飞书 / Bark / Server酱 / WxPusher / Gotify / OneBot 各不一样），不用自己写 JSON。
规则里的「报文体模板」这时表示消息正文（留空则原样透传入站报文）， 「邮件主题模板」表示标题（留空会自动生成一个）。

Telegram 发送（Bot API）

转发过去的正文会当成一条文本消息发出，长度按 Telegram 的规矩最多 4096 个字符 （超出会直接判失败，不会截断）。
怎么拿 Chat ID：把 bot 拉进群（频道里要给它管理员权限），在群里发一条消息， 然后浏览器打开 <请求端点><Bot Token>/getUpdates， 回复里 result[].message.chat.id 就是；私聊则要先给 bot 发一条消息。 频道也可以直接填 @频道用户名。
话题 ID：只在论坛群（forum）里想固定发到某个话题时才填， 话题链接 t.me/c/…/<话题ID> 或 t.me/<群>/<话题ID> 里的那个数字就是它。
Token 是能操作这个 bot 的凭据，出现在投递日志里的地址不会被记录（出错时会把 Token 抹成 ***），但也别把它贴到别处。

邮件接收（IMAP 轮询）

只处理未读邮件，处理成功后标记为已读 —— 所以同一封邮件不会被转发两次， 但也意味着你在邮箱里手动标成已读的邮件不会被处理。 轮询间隔小于 10 秒会按 60 秒处理（对邮件服务器礼貌一点，也不容易被封）。
注意：选「不加密」时密码是明文传输的，只在可信内网里这么用。
